# DriveFollow：汽车销售跟进与试驾邀约 Agent

## 一句话定位
帮助汽车销售顾问基于客户记录、车型知识与门店规则，准备下一步跟进方案，经顾问确认后创建待办或登记试驾，并保留反馈与执行记录。

状态：可运行概念验证；尚未完成真实顾问访谈或业务试点。车型全部为蔚来官网可核查的真实车型，服务摘要来自官方页面；客户、门店和预约为模拟数据。本项目非蔚来官方产品。演示业务日期为 2026-11-19。

## 用户与待验证问题
目标用户：汽车一线销售顾问。

待验证假设：顾问需要在分散的客户历史与产品规则之间切换，决定先联系谁、沟通什么，以及怎样记录下一步行动。这些步骤的频率、耗时和现有工具的不足，需要通过具体任务回放确认。

## 关键产品取舍
- 先做一个完整的试驾邀约任务，减少对完整 CRM、真实触达渠道与门店集成的依赖。
- 工作优先级说明排序依据，不宣称预测成交概率。
- 规则逻辑负责联系边界、有效期与写入约束；可选模型负责措辞，仍需顾问核查。
- 默认无需模型 API Key，使用明确标注的规则模式。配置服务端模型适配器后可实际请求 Chat Completions 兼容接口。
- 只有客户明确确认时间，才能登记模拟预约；档期冲突与重复提交由程序控制。

## Demo 功能
1. 客户搜索、状态筛选、优先级排序、客户新建与事实修改。
2. 生成建议、查看执行步骤与原始资料、编辑和复制草稿。
3. 采用并创建待办；拒绝建议时记录原因。
4. 确认模拟试驾，阻止未确认或冲突的预约。
5. 记录联系结果与后续行动；客户管线与待办列表。
6. 查看知识资料、实际运行规则评测、查看反馈、导出 JSON 和重置演示。

## 证据边界
已实现：本地业务规则、界面与 API、浏览器持久化、可选模型适配器。

合成评测涵盖：正常邀约、拒绝联系、未解决投诉、缺失预算、过期活动、未确认预约、档期冲突和重复待办。它不证明模型质量、用户满意度或商业收益。

未验证：真实顾问需求优先级、用户采用情况、节省时间、有效预约和到店提升、真实模型服务质量及真实 CRM 接入。

## 蔚来知识库：从资料到可核查建议

2026-11-19 采集蔚来官方页面，整理 19 条知识，覆盖 ES6、ET5、ET5T、ET7、ES8 六/七座版、ES8 大五座版、ES9，以及补能、服务无忧、售后和 NIO House。这是一批已核查页面，尚未覆盖 ET9、EC6、EC7。

- 官方事实：保留官网 URL、采集日期和版本；内容为摘要，非逐字原文。
- 定位推断：7 类车型适配人群属于销售假设，需顾问提问确认；不冒充调研结果，也不写入客户事实。
- 销售边界：配置按版本核对；不直接承诺价格、优惠、固定续航、辅助驾驶替代驾驶或固定服务权益。
- 时效管理：换电/充电等数量按采集日记录，服务中心数据截至 2026-10-31。信息不自动更新，实际可用性以官方地图或 NIO App 为准。
- 检索约束：按车型和有效期筛选，仅使用有官方依据的真实车型资料；使用确定性筛选，尚未接入向量检索。

主要来源：[车型官网](https://www.nio.cn/)、[NIO Power](https://www.nio.cn/nio-power)、[NIO Service](https://www.nio.cn/nio-service)、[NIO House](https://www.nio.cn/nio-house)。每条车型资料保留对应详情页链接。

## 下一步验证
- 访谈 3—5 位顾问，请他们回放最近一次跟进任务，校正假设和规则。
- 由顾问制定评审标准，比较人工流程与 Agent 辅助流程的总耗时、事实正确性和修改情况。
- 建立独立留出案例，记录失败原因，验证一次实质迭代。
- 有门店试点后再按固定观察窗口、分组和去重口径衡量预约与到店。没有实测数据前，不填写提升百分比。
