# 连续案例验收与证据边界

2026-11-23 · 新案例均为开发/回归情形，参考行为由 AI 助手依据产品约束编写。下面是可重复操作的验收，不是独立用户研究。

| ID | 输入或操作 | 必须观察到的行为 |
| --- | --- | --- |
| A01 | 有点贵、最近不急、问落地价 | 保留价格咨询/顾虑，时间待确认；不直接拒绝或升高意向 |
| A02 | 我可没说不买 | 否定范围不按“不买”两个字误判拒绝 |
| A03 | 询价后追加“那分三年呢” | 保留上下文的融资咨询；不编造月供 |
| A04 | 不要电话，报价发已有企微 | 电话拒绝；企微只允许本次报价，营销用途仍未知 |
| A05 | 过期/不可用报价资料 | 不创建可发送的报价动作；咨询仍保留 |
| A06 | 客户说已加企微 | 关系仍待核验；不能由原话直接变成系统验证成功 |
| A07 | 建任务后撤回许可 | 相关未执行联系动作取消；执行时也不能绕过 |
| A08 | 连续确认两次 | 不生成两个同一承接任务；创建不等于已联系 |
| A09 | 建任务后改条件或知识状态 | 旧任务不能带旧依据执行，要求重新核实/确认 |
| A10 | 刷新、导出、重置、损坏存储 | 恢复本案例，导出可追溯；不改旧工作台客户记录 |

## 如何亲手验收

1. 从简历原链接进入个人小岛或专业作品集，打开“观望询价”案例。
2. 检查初始原话与缺项，补齐报价条件；模拟资料有效/过期/不可用。
3. 追加限定渠道许可；核实关系后人工确认，查看待办及其证据。
4. 重复确认、改变条件、撤回许可并尝试执行，检查阻断与状态变化。
5. 刷新后核对记录，导出本次 JSON；重置时仅清除本案例。

## 三类记录分别读

- V5 72 条保存输出：12 开发+24冻结样例各跑两个规则；冻结组9/24→18/24，六条失败保留。这些结果来自旧规则，未被本轮代码改写。
- V7 工程行为测试：新规则和状态约束的开发/回归检查，用来证明所测路径；不报告成“真实语义准确率”。
- 真实模型、一线任务与业务数据：本轮没有执行记录，仍待补证。没有新增真实转化、净省人力或渠道接入结论。
