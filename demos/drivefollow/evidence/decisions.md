# 产品判断与技术选择

## 为什么拆开判断
意向、知识和联系许可分别回答三个问题：客户是否还在咨询、资料是否足够回答、当前是否允许行动。知识不足进入核实，联系许可缺失进入确认，不用一个标签覆盖所有状态。

| 产品问题 | 选择 | 设计价值 |
| --- | --- | --- |
| 单句情绪掩盖咨询诉求 | 保留原话轮次，字段关联来源 | 顾问可以检查判断依据 |
| 客户说已加企微 | 客户自述与关系核验分别存储 | 联系前检查当前关系 |
| 报价条件发生变化 | 核验关联条件版本 | 避免沿用旧报价依据 |
| 建单与执行混在一起 | 人工确认后建单，独立执行 | 显式呈现责任和任务进度 |
| 重复确认、客户撤回 | 幂等建单、取消待办、执行前复查 | 控制重复动作和过期任务 |

## 同一任务的方案比较
| 方案 | 适用环节 | 取舍 |
| --- | --- | --- |
| 结构化销售工作台 | 顾问已有客户字段，需要准备跟进 | 输入明确，适合资料引用、草稿与预约管理 |
| 连续询价状态流 | 逐轮澄清、限定许可、变更与撤回 | 使用有限规则，可重复检查每一条状态变化 |
| 模型辅助草稿 | 已有事实与资料，需要组织表达 | 销售工作台提供可配置接口，事实与执行仍经校验 |

## 实现结构
JavaScript 状态模块负责字段、许可和任务约束；页面负责输入与交互；浏览器存储保存对话及任务。模块按职责分开，便于测试同一输入在不同状态下的处理结果。
